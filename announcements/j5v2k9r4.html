🐢 傳統 LLM (System Two 慢思考) 痛苦繁瑣

為了做個分類或判斷，你必須寫落落長的 Prompt，祈禱它按照 JSON 格式吐出文字：

1. 寫複雜 Prompt：「你是一個客服助手，請務必只回傳合法 JSON...」
2. 慢速生成：「好的！以下是您的分析結果：```json...」
3. 程式端 Regex / JSON.parse() 暴力解析（常遇到 Markdown 或未閉合報錯）
4. 延遲 2~4 秒、花費昂貴、高併發直接卡死
⚡ Jev (System One 快思考) 純粹結構化

直接丟 state (狀態/物件) + 有型別的 questions (原子問題)：

1. 傳入 State (原始工單、JSON 或文章字串)
2. 提出有型別的原子問題 (Noul / Choice / Score)
3. 模型平行評估，直接回傳強型別機率與數值
4. 程式碼直接 if response.noul > 0.8: 完美呼叫！
🧱 核心原子：3 個 AI Primitive 互動實測
可任意組合的基石

Jev 拋棄了千變萬化的自由文本，專注於打造 3 個如基本型別（int, bool, enum）般穩健可靠的 AI Primitive。所有問題在模型內部完全平行評估，增加問題幾乎不增加延遲：

Noul：這句話是真的嗎？ (Yes / No 概率)

回傳 0.0 ~ 1.0 浮點數

不是生硬的 True/False，而是經由精準校準（Calibrated）的真實機率值。你可以根據業務風控嚴格度自訂門檻（如 > 0.85 判定為真）。

實測情境： 客訴文字：「我被收了兩次錢，請盡快退款！」
問題設定： Noul(instructions="這張工單是有關帳單計費 (Billing) 嗎？")
判定機率 (Probability)： 0.982 (98.2% 為真)

Choice：從列表中挑選最符合的項目

回傳 choice + probabilities + confidence

給予候選字典（Criteria），模型自動做語意比對與多分類判定，並附帶各選項的置信度。

問題設定： Choice(criteria={"calm": None, "frustrated": None, "angry": None})
calm (冷靜): 2.1% frustrated (沮喪焦急): 78.4% ★ 獲選 angry (憤怒): 19.5%

Score：在有序量表上打分評估

回傳 score + distribution

適用於具有順序性或嚴重度梯度的場景（如：can wait ➔ this week ➔ today，或優先度 1~5 星）。

問題設定： Score(criteria=["can wait (可稍後處理)", "this week (本週內)", "today (今日急件)"])
🔥 判定評分：today (今日急件) (信心度 Confidence: 91.5%)
🐍 Python SDK 快速上手
極簡現代非同步 API

安裝 typesafe-sdk 後，只需短短幾行即可平行呼叫多個問題，完全不需要寫任何解析代碼：

# 安裝 SDK: pip install typesafe-sdk from typesafe_sdk import AsyncTypeSafeClient, Noul, Choice, Score async def evaluate_ticket(): async with AsyncTypeSafeClient() as client: response = await client.system_one( state = { "document": "I was charged twice. Please fix this ASAP." }, questions = { "is_billing": Noul(instructions="Is this ticket about billing?"), "tone": Choice( instructions="What is the customer's tone?", criteria={"calm": None, "frustrated": None, "angry": None}, ), "urgency": Score( instructions="How urgent is this ticket?", criteria=["can wait", "this week", "today"], ), }, ) # 程式直接以強型別欄位存取！零字串處理 if response.nouls["is_billing"].noul > 0.8: route_to_finance_team() print(response.choices["tone"].choice) # 輸出: "frustrated" print(response.scores["urgency"].score) # 輸出: "today"

企業級剛需

情境：審核 AI 客服的回覆是否違反公司法規？

如果讓 AI 自由與客戶對談，最怕 AI 被客戶話術帶偏，私自向客戶承諾賠償。
這個場景是傳統 Regex 程式碼做不到、端側小模型做不到、傳統 GPT-4 太貴太慢的絕佳例子：

👤 客戶來信：
「我這個月被你們扣了兩次費用，請馬上處理，否則我立刻退訂並投訴消保官！」
🤖 初階 AI 客服回覆：
「非常抱歉造成您的困擾！我已經為您申請了全額退款，款項預計 3~5 個工作天退回您的原付款帳戶。」
🔍 Jev 監考官毫秒級即時風控裁決：
promised_refund (AI 是否承諾退款？)
⚠️ 是 (Noul: 0.992)
policy_violation (未經主管核准私自承諾退款)
🚨 嚴重違規！(Noul: 0.985)
churn_risk (客戶流失風險評估)
🔥 極高 (Score: "高")
💡 為什麼其他方案都不行？
  • 傳統 Code 不行： 寫 if "退款" in reply 會誤殺「我們政策規定無法退款」的否定句。
  • 端側小模型 (Needle) 不行： 45M 參數與有限長度無法進行跨語意合規邏輯推導。
  • GPT-4 不適合： 每天 10 萬封對話，用 GPT-4 複查每個月要花數千美元且每次延遲 2 秒；Jev 只要 $4 美元且 80ms 內完成阻截！
🏗️ 正確系統架構：RAG 三層協同模式
Jev 扮演大腦主管

許多人誤以為 Jev 可以當成客服本身——不行！Jev 不會說話、不會生成聊天文字。它是決策大腦與主管，而不是話筒。
現代最推薦的企業級架構是「檢索、決策、說話」三層分工：

Layer 1 感知與知識庫

RAG (語意向量檢索)

當客戶詢問「我可以帶自己的飲料進場嗎？」，RAG 從企業數千頁規章中撈出最相關的 5 條規章（如：禁止外食、嬰兒食品例外、有蓋飲料規定）。

Layer 2 ★ 核心 決策與風控大腦

Jev (System One 裁決 API)

將問題與 5 條規章作為 state 餵給 Jev：
- Choice：這 5 條中哪一條是精確準則？
- Noul：依此準則，客戶到底能不能帶？（回傳 0.94）
- Noul：這需要轉接人工主管嗎？（回傳 0.02）

Layer 3 對話話筒 (Voice)

Generative LLM (GPT-4 / Claude)

只有當 Jev 裁決「可以帶」且「無需轉人工」時，才調用昂貴的生成模型，依據第 2 條規章生成親切體面的回覆語句。徹底消滅 AI 胡言亂語的風險！

🚗 Jev 能做 OCR 嗎？可以把車牌辨識改成 7 個選擇題嗎？

答案是：目前不行！
1. Jev 目前是純文字與結構化狀態，不支援多模態圖片輸入。
2. 理論上若把台灣 7 碼車牌拆成 7 個 36 選 1 的 Choice，會產生 $36^7$ 組合爆炸，且無圖可看。
正確 Pattern 是「雙層組合」： 先用 PaddleOCR 或 Vision LLM 識別出文字 ABC-1234，再由 Jev 秒速檢核「這是否符合台灣車牌編碼邏輯」與「信賴等級」！
