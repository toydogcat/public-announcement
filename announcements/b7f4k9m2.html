0️⃣ 對稱式加密 (Symmetric)：效能王者與致命死穴
經典但有痛點
⚡
運算極快 (硬體加速)
加解密使用同一把金鑰 K。就像用同一把實體鑰匙鎖上門箱，收件人也必須拿同一把鑰匙開箱。
優勢： 運算效能極高，CPU 有專屬 AES-NI 硬體指令集，適合傳送海量串流、硬碟磁碟機加密 (BitLocker)、ZIP 壓縮檔加密。
💥
痛點一：金鑰分發困境
雙方通訊前，必須先共享這把金鑰。
但問題來了：在充滿駭客監聽的公開網路上，你怎麼把第一把金鑰安全寄給對方？ 若把金鑰直接傳過去被截獲，後續加密全數形同虛設！
📈
痛點二：管理成本爆炸
若系統中有 $N$ 個人彼此要獨立安全通訊，總共需要維護：
N × (N - 1) ÷ 2 把獨立金鑰。
全公司如果有 1,000 人，就需要維護 499,500 把金鑰，金鑰管理成本直接失控爆炸！
1️⃣ 非對稱加密 (Asymmetric)：成對雙金鑰的魔法
數學劃時代突破

非對稱加密徹底解決了金鑰分發難題。它使用一對數學上緊密綁定、功能互補的雙金鑰（Public Key & Private Key）：

🌐
Public Key (公鑰)
公開給全世界： 任何人都可以自由取得並儲存你的公鑰，就像印在名片上的電子郵件或統編一樣，完全無需保密！

扮演的兩大角色：
  • 公開的鎖頭： 想寄悄悄話給你的人，用它把訊息鎖起來。
  • 公開的驗章機： 任何人都能拿它驗證你的簽名是否真確。
🔒
Private Key (私鑰)
嚴格保密，僅限本人： 存放於伺服器嚴格隔離區或手機安全晶片 (Secure Enclave)，誓死不可外洩！

扮演的兩大角色：
  • 唯一的開鎖鑰匙： 只有你能解開別人用你公鑰加密的密文。
  • 專屬防偽印章： 只有你能蓋出對應公鑰可驗證的數位簽章。

🎯 核心機制一：資料保密 (Encryption)

口訣：公鑰鎖門，私鑰開門

情境： 你想傳「秘密密碼」給小美。
流程： 向小美索取她的 Public Key，在自己電腦把明文鎖成亂碼送出。小美收到後，用她手上的 Private Key 開鎖還原。
關鍵： 想傳給誰看，就用誰的公鑰鎖門！路上即使封包被竊聽，沒有小美的私鑰就只是無解天書。

🔏 核心機制二：身分證明 (Digital Signature)

口訣：私鑰蓋章，公鑰驗章

目的： 證明「這段話真的是我發的，且中途未被篡改」。
三大保證：

  1. 身分不可冒用： 全世界只有你有私鑰，唯你能產出合法簽章。
  2. 內容不可竄改： 傳輸中改動一個字元，公鑰驗證必然失敗。
  3. 事後不可否認 (Non-repudiation)： 無法狡辯「訊息不是我發的」。

🌐 現代 HTTPS 的智慧：混合加密架構 (Hybrid)
兩全其美設計

對稱加密極快但難換金鑰；非對稱加密能安全換金鑰但運算慢千倍。那現代網際網路（HTTPS、TLS 1.3）怎麼做？
答案是：成年人不做選擇，全都要！這就是「混合加密架構」：

STAGE 1 • 簽章防偽
1. 驗證身分 (數位簽章)
瀏覽器連線到伺服器時，伺服器出示由權威 CA 憑證機構私鑰簽署 的 SSL 憑證。
瀏覽器用內建的 CA 公鑰驗證簽章，百分之百確認：「我連到的是真正的 google.com，不是中間人釣魚伺服器！」
STAGE 2 • 非對稱破局
2. 交換金鑰 (非對稱)
雙方利用非對稱加密（或 Diffie-Hellman 橢圓曲線金鑰協商 ECDHE），在處處被監聽的公開網路上，安全協商出一組臨時且隨機的 「Session Key 對稱金鑰」！
STAGE 3 • 對稱式狂飆
3. 高速傳輸 (對稱加密)
連線安全建立後，後續龐大的 HTML、圖片、影音串流及 JSON API 傳輸，全數改用 AES-GCM / ChaCha20 對稱加密 狂飆，兼顧資安防護與毫秒級超低延遲！
🔑 Passkey / Face ID 到底在驗證什麼？
WebAuthn 革命

🚨 大眾常見誤解：「Face ID 把我的臉部照片傳給伺服器進行比對？」

👉 絕對不是！伺服器連你一根睫毛的資料都沒拿到！

1. 生物辨識僅限本地：

Face ID / 指紋只用於在手機本地解鎖專屬硬體安全晶片 (Secure Enclave)。

2. 私鑰永不出機：

解鎖後，安全晶片動用儲存於晶片內的 Private Key 對伺服器的挑戰題目進行簽署。

3. 零個資洩漏風險：

伺服器只保管你註冊時上傳的 Public Key，驗章通過即登入。就算伺服器被駭客拖庫，也偷不到你的生物特徵！

🛡️ Challenge-Response（挑戰-應答）：徹底防範重播攻擊 (Replay Attack)

如果駭客在網路上把你登入時傳送的「簽章封包」錄下來，直接重發一遍（重播攻擊），能不能偷偷登入？
答案是：絕不可能！因為伺服器每一次出的題目（Nonce）都是隨機且單次有效的！

1
用戶發起請求
「我是王大明，想登入帳戶」
2
隨機挑戰題目
伺服器發送單次隨機亂數 Nonce: ABC-9812
3
本地私鑰簽章
Face ID 解鎖晶片，以 Private Key 對 Nonce 計算 Signature
4
公鑰驗證放行
伺服器拿 Public Key 驗章通過，銷毀 Nonce
🧠 工程師必背的五句密碼學心智模型
一輩子受用架構記憶
MODEL 01
對稱加密效能王者
同一把鑰匙鎖門開門，適合海量資料傳輸，但必須解決鑰匙怎麼給對方的致命難題。
MODEL 02
公鑰可公諸於世，私鑰誓死自己留
私鑰只要離開設備或被儲存到雲端資料庫，整個密碼學信任鏈立刻瓦解。
MODEL 03
公鑰鎖門 (加密)，私鑰開門 (解密)
想傳秘密給誰，就拿誰的 Public Key 鎖門，全世界只有擁有該私鑰的本人打得開。
MODEL 04
私鑰蓋章 (簽名)，公鑰驗章 (驗身分)
想向全世界證明是我發出的指令，就拿自己的 Private Key 蓋章，任何人都能用公鑰驗證真偽。
MODEL 05
實戰永遠是混合架構 (Hybrid)
HTTPS 與 SSH 先用非對稱驗證身分與安全換金鑰，再用對稱加密狂飆速度傳輸。

🛡️ 建立穩健的系統資安視野

掌握公私鑰的兩大超能力（開鎖與蓋章），現代密碼學所有核心技術與協定都將迎刃而解：

🛡️ Identity & Auth (身分與驗證) 🔒 Data Confidentiality (資料保密) ✔️ Non-Repudiation (不可否認性)

無論是設定 ~/.ssh/id_rsa.pub、驗證 JWT RS256 簽名、還是開發 WebAuthn Passkey，底層全都是這套永恆不變的優雅邏輯！
