Architecture & Engine

🧬 JIT 協定演化三階段：兼具極致靈活性與極速效能

如何做到既能理解使用者的模糊自然語言，又能在高併發場景下達到原生靜態代碼的極致速度？

Phase 1: Dynamic

動態語意探索

接受模糊查詢與非結構化請求（例如：「我想買 iPad 刷 LinePay 金額 25900」）。由 TypeSafe Jev 雲端或本地 Needle 引擎進行語意意圖匹配與實體萃取。

延遲: 1 ~ 8ms (AI / 語意分析)
狀態: 觀測與學習階段
Phase 2: Observing

結構穩定性觀測

內建連續觀測器（Stability Observer）。每次請求均比對 Payload 結構與置信度，當連續 3 次請求結構一致且置信度達 85% 時，自動觸發「合約凍結（Freeze）」。

門檻: 連續 3 次結構一致
動作: 自動編譯 TypeScript / Protobuf
Phase 3: Frozen

極速靜態快路 (0ms)

編譯出純靜態驗證器。往後符合格式的請求直接走快路執行，完全跳過 AI 呼叫，達到 0ms AI 延遲！若遇到結構突變（Schema Drift），自動無痛降級回 Phase 1 重新演化。

延遲: 0ms (純原生代碼執行)
防護: 結構突變自動降級重訓
Step-by-Step Guide

🚀 3 分鐘起手式：小白也能輕鬆上手的後端開發

無須繁雜的 Docker 或伺服器配置，只要有 Node.js 環境即可使用 `npx` 隨處運行。

1

一鍵初始化規格目錄

在任意空白資料夾或專案根目錄中建立規格檔

在終端機輸入以下指令，jit-api 將會自動建立 specs/ 目錄與初始範本檔案 order.api.md：

Bash 
npx -y jit-api@1.1.1 init
2

看懂並撰寫你的 Markdown API 規格

一個文件搞定：路由、意圖、型別、範例與業務邏輯

以下是 v1.1.1 標準規範範本，以陽曆農曆與時間戳轉換 API 為例：

Markdown (specs/date_converter.api.md) 
# API: date_converter
Version: 1.1.1
Stage: prod
> 日期轉換中心：支援 Timestamp 時間戳、陽曆與陰曆雙向精準互換

## Intent
User wants to convert dates, unix timestamp, solar to lunar calendar, or lunar to solar

## Fields
- action: enum (轉換模式)
  - SOLAR_TO_LUNAR: 陽曆轉陰曆
  - LUNAR_TO_SOLAR: 陰曆轉陽曆
  - FROM_TIMESTAMP: 時間戳轉日期
- date: string (陽曆日期如 2026-09-23)
- timestamp: number (Unix 時間戳)

## Sample
- Semantic: 我想將國曆 2026 年 9 月 23 日轉換為農曆陰曆與時間戳
- Payload:
```json
{
  "action": "SOLAR_TO_LUNAR",
  "date": "2026-09-23"
}
```

## Logic
```javascript
// 純粹的 JavaScript 業務邏輯，ctx.phase 代表當前演化階段
const pad = (n) => String(n).padStart(2, '0');
const target = payload.date ? new Date(payload.date) : new Date();
return {
  status: "SUCCESS",
  solar_date: target.toISOString().split('T')[0],
  timestamp_seconds: Math.floor(target.getTime() / 1000),
  phase: ctx.phase,
  ai_latency_ms: ctx.aiLatencyMs
};
```
3

啟動開發者儀表板 (Dev Mode)

動態熱重載、Web Studio、整合終端與即時測試

輸入以下指令開啟開發環境。預設自動在 http://localhost:3005 啟動控制台，若遇連接埠佔用會自動安全遞增：

Bash 
npx -y jit-api@1.1.1 dev

# 若想要指定自訂 Port:
npx -y jit-api@1.1.1 dev --port 3006
  • 📂 規格熱重載：修改 specs/*.api.md 後存檔，約 200ms 自動加載更新。
  • 💻 Web 終端：儀表板底部自帶 PTY 終端抽屜，無需在 IDE 與瀏覽器間頻繁切換。
  • 🎯 動態 Payload：點擊「語意意圖請求」或「穩定快路請求」，自動灌入規格定義的真實 Payload。
4

一鍵部署生產模式 (Prod Mode)

關閉敏感端點、唯讀規格防護、隔離草稿 API

在生產伺服器上，只需使用 prod 或 start 指令：

Bash 
# 標準生產模式 (預設 Port: 3000，唯讀儀表板)
npx -y jit-api@1.1.1 prod

# 雲原生微服務純 API 模式 (完全關閉 Web 介面，極低記憶體開銷)
npx -y jit-api@1.1.1 prod --headless
5

發布版本快照與秒級安全回滾 (Release & Rollback)

不怕線上發布出錯，孤兒規格自動備份隔離

Bash 
# 建立規格版本快照
npx -y jit-api@1.1.1 release 1.0.0 "首發穩定版"

# 線上發生突發狀況？秒級回滾至指定版本！
npx -y jit-api@1.1.1 rollback 1.0.0

💡 v1.1.1 亮點：當降版時，若當前目錄存在該歷史版本中沒有的「孤兒規格」，系統會自動將其備份隔離至 .jit/releases/orphaned_*/，絕不遺失任何代碼。

Security & Operations

⚖️ 開發模式 vs 生產模式：全方位安全性對比

jit-api 在兼顧極致靈活的同時，為生產環境提供了嚴格的零信任保護。

特性維度 DEV 模式 (npx jit-api dev) PROD 模式 (npx jit-api prod)
預設連接埠 Port 3005（遇衝突自動嘗試 3006, 3007...） Port 3000（遇衝突自動嘗試 3001, 3002...）
API 規格載入範圍 全部載入（含 Stage: dev 草稿規格） 僅載入 Stage: prod 規格，草稿不外洩
Web Studio 儀表板 全面開啟（視覺化測試、線上壓測、合約匯出） 唯讀狀態（或加上 --headless 完全關閉）
Web 終端 (PTY) 開啟（底部自帶虛擬終端） 完全停用（阻斷遠端指令注入風險）
HTTP 線上規格編輯 允許（POST /api/specs/:file） 嚴格封鎖（直接回應 403 Forbidden）
規格自動熱重載 啟用（fs.watch 約 200ms 動態更新） 停用（靜態鎖定，確保高吞吐穩定度）
MCP AI 工具鏈掛載 開啟（掛載全部工具） 開啟（僅掛載生產級可用工具）
Evolution & Roadmap

🗺️ 版本演化進程：踏實邁向雲原生 JIT 生態

持續傾聽開發者反饋，快速疊代，打造下一代協定合成標準。

v1.0.0 - 初代誕生 2026 年初
  • JIT 動態協定合成核心引擎問世。
  • Markdown 規格解析驅動 API 端點。
  • 整合 Web Studio 觀測儀表板與整合式 PTY 終端。
v1.1.0 - Dev/Prod 雙模與版本快照 2026 年 9 月
  • 導入 dev 與 prod 模式安全分流。
  • 新增規格版本快照發布 (release) 與降版 (rollback)。
  • 支援 ## Sample 區塊，解決範例 Payload 硬編碼痛點。
v1.1.1 - 現行穩定版 (Current Stable) 🌟 最新發布
  • 資安漏洞修復：修復 MCPAdapter 穿透漏過 Dev 草稿規格的問題。
  • 容錯重試：連接埠佔用時自動優雅遞增切換 (EADDRINUSE)，不再拋錯崩潰。
  • 純網關模式：新增 --headless 參數，專為微服務容器化設計。
  • 智慧隔離：Rollback 時自動將孤兒規格隔離至 .jit/releases/orphaned_*/。
  • 前端防護：生產模式自動隱藏終端機抽屜並鎖定規格儲存按鈕。
v1.2.0+ - 未來演化藍圖 (Coming Soon) 規劃中
  • 分散式快路快取：支援 Redis / Upstash，凍結合約跨節點同步。
  • 雙向契約轉換：支援 OpenAPI 3.1 與 Markdown 規格雙向匯入匯出。
  • 靜態二進位編譯：支援一鍵匯出 Go / Rust 高吞吐微服務單一檔案。
  • 鑑權插件系統：內建 JWT、API Key 與 OAuth2 權限守衛。
Review & Takeaways

💬 研發實踐心得：為什麼 jit-api 值得你在下個專案採用？

💡 「文檔即後端」消除溝通死角

在團隊協作中，最常發生的問題是前端看著過期的 Swagger 發呆。jit-api 的 Markdown 規格就是運行的邏輯，規格更新了，API 就立刻更新，真正實現「零同步成本」。

🤖 AI 時代的 Agent-Native 架構

不用另外花時間寫 MCP Adapter！寫好 Markdown 規格後，Cursor、Claude 或自研 AI Agent 可以透過內建的 /sse 入口直接將你的 API 作為工具（Tools）呼叫，無縫擁抱智慧代理時代。

🛡️ 優雅平滑的漸進式凍結

你可以在前期隨意修改與讓 AI 寬鬆匹配；等到系統成熟、結構穩定時，引擎會自動接管變成 0ms 快路。這種「前期靈活、後期極速」的特質，是傳統框架難以企及的。
