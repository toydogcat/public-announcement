報告簡介與核心診斷結論

交通部運輸資料流通服務（TDX）做為台灣智慧交通的數位基礎建設，扮演著整合全國動靜態運輸資料（公車、軌道、自行車、停車等）的核心開放 API 入口。 本報告針對第三方平台的評測數據，深度解構其在 AEO（人工智慧搜尋引擎最佳化） 的表現，以及 PageSpeed Insights（網頁載入體驗） 的效能缺口。 我們發現，TDX 的資料權威性與政府背書極高，但在面對 LLM 語意檢索 以及 行動端效能指標 (Core Web Vitals) 時，仍存在高度可優化的技術壁壘（如結構化標記缺失與桌面端高達 0.401 的 CLS 版面位移問題）。

🔍 AEO 深度解析：為什麼 AI 搜尋時代必須做 Schema.org 標記？

  • 傳統 SEO 已死，AEO (AI 搜尋引擎優化) 成為新戰場
    當使用者詢問「TDX 提供哪些公車 API？」或「如何呼叫台北市公車即時預估到站時間 API？」時，AI 搜尋引擎（如 SearchGPT, Perplexity）不會只拋出連結，而是直接提供程式碼和 API 詳細參數。若 TDX 官網缺乏 Schema 結構化資料，AI 無法高效提取其 OData 與 WebAPI 規格，將導致 AI 直接引用非官方的二手資料，甚至產生幻覺。
  • 關鍵缺口：缺乏 Dataset 與 WebAPI 的 JSON-LD 標記
    評測顯示 TDX 網站雖然有 Swagger 開發文件，但在網頁前端的 HTML 中，並未鋪設 Schema.org 的 Dataset（數據集）與 WebAPI（網路接口）結構化腳本。這使得搜尋引擎爬蟲和 LLM 只能以普通網頁文字形式閱讀文件，大幅降低了在 Knowledge Graph（知識圖譜）中的實體關聯權重。
  • 優化方案：在 API 詳情頁面埋入 JSON-LD
    TDX 應在所有主要的 API 產品頁面上，動態生成並注入符合 Schema.org 標準的結構化資訊，讓 AI 能立刻辨識該 API 的傳入參數、回傳欄位、授權方式與服務提供者（交通部）。（可在「原始數據與代碼」分頁中複製完整範例代碼）

⚡ 網頁效能瓶頸重點診斷與優化解方

  • 嚴重警報：消除會阻斷算繪的資源 (預估可省下 2,130 毫秒)
    網頁在 <head> 中同步載入了大型的 CSS 與 JavaScript 檔案，導致瀏覽器必須先下載並解析完這些資源才開始畫頁面。 建議： 將非核心的 JS 加上 defer 或 async，並將關鍵 CSS 內聯 (Critical CSS)，其餘 CSS 異步載入，以大幅降低手機端的 FCP 與 LCP。
  • 體驗地雷：桌面端 CLS 版面配置偏移 (0.401) 的根源
    Lighthouse 指出，桌面端最大的位移源自於 強制自動重排 (Forced Reflow) 以及 圖片元素沒有明確定義 width 與 height。當圖片或動態地圖區塊載入完成後，其高度突然從 0 撐開，導致下方所有選單與文字被瞬間往下擠。 建議： 在所有圖片與圖表 SVG 的 HTML 標籤上明確標記寬高比，或使用 CSS 的 aspect-ratio 屬性預留版面空間。
  • 效能低碳：字型顯示與快取生命週期 (Cache Policy)
    評測顯示網頁字型載入時未設定 font-display: swap，導致字型下載完成前網頁文字會隱形（白屏的一部分）。另外，快取生命週期設定過短（預估可省下 308-528 KiB 的重複資料傳輸）。 建議： 在 @font-face 中加入 font-display: swap。並在服務器端將靜態資源（CSS, JS, 圖片）的 Cache-Control 設為一年。

🛠️ 建議部署：TDX API 專用 Dataset 結構化資料代碼 (JSON-LD)

將以下腳本放置於 TDX API 詳情頁（例如 /data-service/api-detail/...）的 <head> 中，可使 LLM 搜尋引擎精確理解 API 資料規格：

{

  "@type": "Dataset",

  "description": "提供全國尺度之公路客運與市區公車路線、站位、時刻表、班次等動靜態資料，以及即時車輛位置、預估到站時間資料",
  "url": "https://tdx.transportdata.tw/data-service/api-detail/PUB_BUS_v3",
  "keywords": ["公共運輸", "公車", "即時", "時刻表", "API", "交通", "開放資料"],
  "provider": {
    "@type": "Organization",
    "name": "交通部運輸資料流通服務"
  },
  "spatialCoverage": "Taiwan",
  "temporalCoverage": "2018-01-01T00:00:00Z/",
  "variableMeasured": ["BusRoute", "BusStop", "RealtimePosition", "EstimatedArrivalTime"],

    {

🛠️ 建議部署：WebAPI 端點結構化標記範例

為個別 API 查詢路徑（如 /Bus/Route/City/{City}）埋設 WebAPI Schema，有利於 AI 代理或代碼生成工具（如 Copilot, Cursor）自動呼叫：

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebAPI",
  "name": "公共運輸-公車-v3 路線API",
  "description": "提供查詢指定縣市之公車路線資料 (Provides bus route data for specified cities)",
  "documentation": "https://tdx.transportdata.tw/api-service/swagger/basic/eb87998f",
  "url": "https://tdx.transportdata.tw/api/basic/v3/Bus/Route/City/{City}",
  "encodingFormat": "application/json",
  "httpMethod": "GET",
  "input": {
    "@type": "EntryPoint",
    "name": "City",
    "parameter": "string (e.g., 'Taipei')",
    "required": true
  },
  "output": {
    "@type": "EntryPoint",
    "name": "BusRoute",
    "description": "公車路線資料陣列 (Array of bus route data)"
  },
  "provider": {
    "@type": "Organization",
    "name": "交通部運輸資料流通服務"
  }
}
</script>
